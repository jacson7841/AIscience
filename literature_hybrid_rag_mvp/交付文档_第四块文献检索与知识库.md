# 第四块交付文档：文献统筹搜索与 RAG 知识库

## 1. 模块定位

本模块对应团队分工中的“文献检索与知识库”，负责把研究主题转化为可检索、可追溯、可供后续 Agent 调用的文献知识底座。

核心目标：

- 从 arXiv、OpenAlex、Semantic Scholar 等来源检索候选论文。
- 对论文进行去重、评分、验证和分层。
- 下载并解析 PDF；PDF 不可用时使用摘要降级入库。
- 构建本地知识库，支持 Hybrid RAG 检索。
- 输出核心论文、相关论文、已有研究结论、研究不足及对应来源。

## 2. 知识库形成方式

本系统采用“先初始化建库，后本地查询”的方式。

第一阶段是 `bootstrap`。系统读取 `seed_topics.json` 中的研究主题，扩展检索式，然后从多个学术来源检索论文。候选论文会统一转成 `PaperRecord`，再通过 DOI、arXiv ID、Semantic Scholar ID 和标准化标题去重。之后系统下载可访问 PDF 并按页解析；如果 PDF 不可访问，则使用摘要作为降级证据。最后将文本切块写入本地知识库，并同步保存 `papers.json`、`chunks.json` 和 `search_manifest.json`。

第二阶段是 `review` 或 `ask`。系统不再从零联网爬取，而是先查询已经建好的本地知识库。这样现场演示更稳定，也能证明知识库确实已经形成。

## 3. 离线 Demo 跑的是什么

离线 demo 命令：

```powershell
python literature_hybrid_rag_mvp\literature_pipeline.py bootstrap --seed literature_hybrid_rag_mvp\seed_topics.json --limit 5 --demo --skip-pdf-download --no-dense
```

这条命令跑的是“功能闭环测试”，不是正式真实文献检索。

各参数含义：

- `--demo`：使用代码内置的 5 条样例论文记录，不访问 arXiv/OpenAlex/Semantic Scholar。
- `--skip-pdf-download`：不下载 PDF，只用摘要生成 chunk。
- `--no-dense`：关闭 Chroma dense retrieval，只使用 JSON 文件和 BM25 稀疏检索，方便离线测试。
- `--limit 5`：最终保留 5 篇样例论文。

因此输出中的：

```text
bootstrap complete: papers=5 chunks=5
```

表示系统成功生成了 5 条论文记录和 5 个文本块。由于 demo 不下载 PDF，所以 `search_manifest.json` 中会显示：

```text
pdf_available: 0
abstract_only: 5
```

`Dense retrieval disabled by configuration` 是正常提示，表示本次为了离线测试关闭了 Chroma 向量检索。

```powershell

```

建议先做小流量联网测试，避免 OpenAlex 或 Semantic Scholar 限流：

```powershell
$env:OPENALEX_MAILTO="你的邮箱@example.com"
python literature_hybrid_rag_mvp\literature_pipeline.py bootstrap --seed literature_hybrid_rag_mvp\seed_topics.json --limit 10 --skip-pdf-download --no-dense --max-queries 3
```

如果出现 `429 Too Many Requests`，表示外部学术 API 限流，不代表本地建库流程失败。此时可以：

- 减小 `--max-queries`，例如设为 `1` 或 `2`。
- 设置真实 `OPENALEX_MAILTO`，提高 OpenAlex 请求稳定性。
- 申请并设置 `SEMANTIC_SCHOLAR_API_KEY`。
- 保留 `--skip-pdf-download --no-dense`，先验证检索和 JSON/TXT 输出链路。
- 等待几分钟后再重试。

## 5. 输出文件说明

输出目录：

```text
literature_hybrid_rag_mvp/
  outputs/
    search_manifest.json
    papers.json
    chunks.json
    literature_review.json
    literature_review.txt
    answer.json
    answer.txt
    warnings.txt
  data_storage/
    knowledge_base/
    pdfs/
```

关键文件：

- `search_manifest.json`：记录检索主题、扩展检索式、各来源返回数、去重数、PDF 成功数、摘要降级数和最终入库数。
- `papers.json`：标准化论文元数据，包含论文 ID、标题、作者、年份、DOI、URL、PDF URL、引用数、来源、相关性分数和可用性分数。
- `chunks.json`：RAG 检索单元，包含 chunk 文本、论文标题、页码、章节、来源 URL 和证据等级。
- `literature_review.json`：给后续模块调用的结构化综述。
- `literature_review.txt`：给答辩展示和人工阅读的文本版综述。
- `answer.txt`：针对某个问题的 RAG 回答及来源。

## 6. 交付内容写法

可以在汇报材料中这样描述：

> 本模块实现了 AI Scientist 系统中的 Literature Intelligence Layer。系统首先根据研究主题进行多源文献统筹搜索，覆盖 arXiv、OpenAlex、Semantic Scholar 和本地 PDF。检索结果经过去重、验证和评分后形成标准化论文记录；可访问 PDF 会被按页解析并切块，不可访问论文则以摘要形式降级入库。知识库存储每个证据片段的论文标题、页码、章节、URL 和证据等级，从而支持可溯源的 RAG 检索。
>
> 查询阶段采用 Hybrid RAG：Dense Retrieval 负责语义相似检索，BM25 负责精确术语匹配，二者合并后交给模型生成结构化结果。输出内容包括核心论文、相关论文、已有研究结论、研究不足和对应来源，并同时生成 JSON 接口文件和 TXT 展示文件。JSON 可直接供后续“假设生成与科研评审”模块调用，TXT 可用于答辩展示。

## 7. 答辩展示建议

展示顺序：

1. 展示 `seed_topics.json`，说明初始研究主题。
2. 运行 `bootstrap`，展示系统如何形成初始知识库。
3. 打开 `search_manifest.json`，说明检索、去重、PDF 获取和入库统计。
4. 打开 `literature_review.txt`，展示核心论文、已有结论和研究不足。
5. 运行 `ask`，展示系统能基于本地知识库回答问题并给出来源。

重点强调：

- 不是简单关键词搜索，而是多源统筹检索。
- 不是一次性问答，而是先形成持久知识库。
- 每条结论和研究不足都保留来源。
- 研究不足采用跨论文推理，置信度受来源数量约束。
- 输出 JSON 可以作为后续 Agent 的输入。
