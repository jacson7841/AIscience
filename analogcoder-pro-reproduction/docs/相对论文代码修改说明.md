# 相对 AnalogCoder-Pro 公开代码的修改说明

## 修改范围概览

主程序 `run.py` 相对下载的公开版本约为 254 行新增、114 行删除。改动目标是让公开代码在本机
Python 3.13/Ngspice 46/百炼环境下可运行、可停止、可追踪，而不是补造仓库缺失的论文优化代码。

## 主闭环修改

| 模块 | 原公开代码 | 本复现修改 | 作用 |
|---|---|---|---|
| 模型配置 | 代码模型和视觉模型共用参数 | 新增 `--vlm-model`，默认代码模型 `qwen3-coder-plus`、视觉模型 `qwen3.7-plus` | 分离生成和波形诊断职责 |
| 百炼配置 | 主要读取 OpenAI 参数 | 读取 `DASHSCOPE_API_KEY`、`BAILIAN_BASE_URL`，同时保留兼容参数 | 不把密钥写入代码 |
| API 重试 | 多处无限循环和固定 sleep | 统一有限重试、延迟参数、认证错误快速失败 | 避免任务无限挂起 |
| VLM 故障 | 视觉请求失败会中断主流程 | 保存 `vlm_error.txt` 并降级为纯仿真反馈 | 辅助模型不再阻断闭环 |
| 子进程 | 调用字符串 `python` | 使用当前 `sys.executable`，统一 UTF-8、`PYTHONPATH` 和 Matplotlib 无头后端 | 保证使用指定 Conda 环境 |
| Ngspice 46 | PySpice 版本白名单会告警 | 注入 `pyspice_runtime.configure_pyspice()` 并使用 shared-library 后端 | 适配 Windows Ngspice 46 |
| 日志 | 分散文本、句柄生命周期不稳 | 修正日志关闭顺序，增加 prompt/answer history 和 JSON 消息记录 | 解决 closed file 错误并便于审计 |
| Token | 主要显示当次调用 | 汇总代码模型与视觉模型 usage，写入每次运行记录 | 可比较成本和修复轮数 |
| 运行状态 | 成败主要靠文件名判断 | 生成 `run_record.json`，记录环境、耗时、API 事件、token、制品和最终状态 | 形成结构化证据 |
| 顶层异常 | 进程异常后缺少统一记录 | 写入 orchestrator failure JSON，认证失败不算正式独立实验 | 区分 API 故障和任务失败 |
| 成功后处理 | 只保存代码和波形 | 自动调用原理图导出链 | 同时交付代码、网表、JSON、SVG、PNG |

## 新增 Python 3.13/Ngspice 运行时

新增 `pyspice_runtime.py`：

1. 从 `NGSPICE_DLL_PATH` 读取 Ngspice 共享库路径。
2. 在 Windows 中注册 DLL 搜索目录并保持句柄存活。
3. 显式设置 PySpice `NgSpiceShared.LIBRARY_PATH`。
4. 将默认仿真器切换为 `ngspice-shared`。

原因是 Windows 的 `ngspice_con.exe -s` 无法向 PySpice 返回所需二进制数据，而 Ngspice 46
shared DLL 在 RC、p1、Task 19 和 LM358 测试中均能正常工作。PySpice 输出的
`Unsupported Ngspice version 46` 是版本白名单告警，不代表仿真未执行。

## 新增 LM358 类迁移任务

`evaluation/lm358_conditioner/` 完全是本复现新增模块：

- `task.md`：定义 5 V 单电源、2.5 V 偏置、增益 5、1 kHz 截止和不削顶规格。
- `run_agent.py`：调用真实模型，初始生成加最多 3 次修复，并保存每次候选和 token。
- `checker.py`：独立执行 DC、AC 和 transient 仿真，按五项确定性规则判定。
- `reference_design.py`：先验证测试台本身，避免把测试台错误误判成模型能力不足。

对模型输出只做机械性的 PySpice 1.5 import 归一化，不修改电路拓扑或元件值。第 2 次独立运行
已能仿真，但模型使用的 10 kOhm/10 kOhm 参考分压器被反馈网络加载，增益只有 3.648 V/V；
把该仿真诊断反馈给模型后，第 3 次运行生成了使用理想 2.5 V 参考的通过方案。

## 新增原理图导出链

`repro_tools/schematic/` 为本复现新增：

1. `export_from_pyspice.py` 执行成功设计并取得 `Circuit` 对象。
2. `netlist_parser.py` 使用结构化 SPICE 解析，识别 R/C/L/V/I/D/E/G/M/Q 及节点连接。
3. `renderer.py` 根据 MOSFET source-to-drain 层级排列 Gilbert Cell。
4. `schemdraw_renderer.py` 对 RC + VCVS 有源调理拓扑使用标准 SchemDraw 元件符号。
5. 输出 `.cir`、元件/节点 JSON、布局 JSON、SVG、PNG 和 manifest。

导出失败与电气测试失败分开记录：电路通过测试后，即使制图失败也不会篡改任务通过结论。

## 新增运行与复现工具

- `check_environment.py`：记录 Python、依赖、Ngspice 路径，并执行最小 RC 工作点验证。
- `run_task19.ps1`：自动识别已有正式运行，归档未完成运行，再续跑到三次。
- `run_lm358.ps1`：运行下一次 LM358 独立实验。
- 两个 PowerShell 入口优先读取 `ANALOGCODER_PYTHON`，否则使用当前环境的 `python`，不再绑定
  某台计算机的 Conda 绝对路径。
- `environment.yml` 与 `requirements.txt`：固定关键依赖，包含 PySpice 1.5 和 SchemDraw 0.23。

- 没有宣称复现论文所有参数优化与消融实验。
- 没有将 LM358 类理想模型结果描述为厂商器件级验证。
- 没有从 Task 19 结果外推系统能够自动完成双向 DC-DC 功率变换器设计。
